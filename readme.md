**To start solving the problem, delete ALL the code within the function body.**



## Solving, Instructions, and Comments
Some instructions are intentionally vague and resemble concepts or overall logic rather than actual solving instructions.

### Solving
Keep this concept in mind for solving: 
> "Use what you have to your disposal". 

Many problem files come with pre-made functions and formulas in their instructions. **Ideally these are implemented as they are usually considered the most efficient solutions to the problem.** Solve however you want, but ensure you are not adding complexity to or brute-forcing the problem *(this may result in point deductions during major exams)*.

### Instructions
Instructions are (intentionally?) vague sometimes and may leave out details about what variables you're expected to use. Infer as much as you can from function parameters and codetracing in the other files. Many of Sir Gran's problems in particular feature "Story" and "Direct" versions of the instructions. **The former offers no added value.**

Each problem will come with a separate MD file for the problem description, instructions, and sample outputs.

### Comments
In relation to vague instructions, I have left comments in some of my code along with solutions. These resemble pseudocode or a way to translate the instructions — which tend to resemble goals more than instructions more than code — into a more descriptive and intuitive way (for me) to approach the problem.
